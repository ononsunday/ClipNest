# 发布与验收

发布前先运行自动化测试、Windows 集成测试和打包后的启动检查。测试只能证明记录中实际运行过的场景；短时间启动检查不能证明数小时后台运行稳定。

## 复现构建

在 Windows PowerShell 中进入项目根目录：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest -q
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
```

默认测试跳过真实快捷键发送与真实剪贴板两项测试。真实剪贴板测试因 OLE 恢复故障已无条件停用；设置 `CLIPNEST_NATIVE_TESTS=1` 也不会启用它。如果只需要追加真实快捷键发送检查，关闭正在输入的任务，执行：

```powershell
$ClipNestPreviousNativeTests = $env:CLIPNEST_NATIVE_TESTS
try {
    $env:CLIPNEST_NATIVE_TESTS = "1"
    .\.venv\Scripts\python.exe -m pytest -q
} finally {
    $env:CLIPNEST_NATIVE_TESTS = $ClipNestPreviousNativeTests
}
```

快捷键测试只在自己的测试窗口获得前台时发送组合键。这不是实际密码管理器或全部应用的兼容性测试。`scripts\verify_paste_native.py` 已禁用，仅保留故障诊断源码；不要重新启用其中的 OLE 保存与恢复流程。

快捷窗口的原生焦点和拖动检查可以单独运行：

```powershell
.\.venv\Scripts\python.exe .\scripts\verify_quick_native.py
```

运行期间请暂时停止鼠标和键盘输入。脚本会打开自己的测试编辑器和快捷窗口，发送鼠标操作与 Enter，结束时尝试恢复原鼠标位置和前台窗口。它使用合成记录、测试复制回调和模拟粘贴回调，不读写系统剪贴板，也不发送真实 Ctrl+V；这项检查验证焦点与交互流程，不验证剪贴板实际内容或真正的粘贴结果。

构建输出在 `dist\ClipNest`，入口为 `ClipNest.exe`。`_internal` 存放 Python、Qt、Pygments 和运行库。不能只复制 EXE。构建中间文件在 `build`，与应用实际使用的历史目录分开。

脚本在构建期间临时缩减 `PATH`，仅保留解释器和 Windows 目录，结束后恢复原值。这避免 PyInstaller 把其他软件附带的同名 DLL 装入发布目录。本机曾遇到 Poppler 的 ICU DLL 被收集，导致 QtCore 缺少所需导出。该问题已修正，重建后没有打包不兼容的 ICU DLL，程序使用 Windows 系统 ICU 并通过启动测试。

可以使用 `-PythonPath "C:\包含空格的路径\python.exe"` 指定解释器。构建脚本用 PowerShell 参数数组传递路径，不拼接为另一条 shell 命令。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1 -Console
```

这条命令生成显示控制台的目录版，适合排查导入或 Qt 插件问题。发给普通用户前，重新执行不带 `-Console` 的默认构建。

## 安装包方案

项目提供 Inno Setup 配置 `scripts\installer.iss`。先构建目录版，再安装 Inno Setup，用编译器执行：

```powershell
& "C:\Program Files (x86)\Inno Setup 6\ISCC.exe" ".\scripts\installer.iss"
```

实际安装位置取决于本机 Inno Setup 的版本和安装路径，请据此修改命令。配置使用当前用户的 `%LOCALAPPDATA%\Programs\ClipNest`，创建开始菜单入口，桌面快捷方式由安装者选择。`PrivilegesRequired=lowest` 不主动请求管理员权限，行为见 [Inno Setup 官方说明](https://jrsoftware.org/ishelp/topic_setup_privilegesrequired.htm)。命令行编译方式见 [官方编译器文档](https://jrsoftware.org/ishelp/topic_compilercmdline.htm)。

预期安装包输出为 `dist\installer\ClipNest-0.1.0-Setup.exe`。这里只提供可复用的制作配置；是否完成编译、安装和卸载验收，以后面的实际测试记录为准。卸载保留 `%LOCALAPPDATA%\ClipNest` 历史数据，安装配置不主动删除用户记录。

目录版已附带 `docs\licenses` 文件夹，包含本机安装包许可原文、Python 许可、GNU 许可全文和文件哈希清单，详见 [第三方组件说明](licenses/THIRD_PARTY_NOTICES.md)。正式发布前，需要按最终打包文件核对各 Qt 模块和内置第三方代码的分发要求、版权声明及对应源码提供方式，再对程序和安装包签名。当前配置没有发布者证书和签名步骤。

## 快捷操作与管理更新

快捷窗口支持单击记录复制并粘贴，搜索后按 Enter 也执行这一操作。默认发送粘贴快捷键后保持窗口，设置中可开启发送成功后自动关闭。应用检查目标窗口与输入焦点，先等待 Enter、Ctrl、Alt、Shift 和 Win 键松开，再恢复目标并发送 Ctrl+V；无法发送时保留已复制内容并显示手动粘贴提示。

生产接口返回成功表示粘贴快捷键已发送，不保证所有目标软件都接受内容。应用不主动执行代码，也不模拟 Enter；粘贴内容的后续处理由目标软件决定。下面独立测试编辑器中的实际插入与选区替换是已观察到的具体结果。

右键记录可以置顶、收藏、删除或仅复制。每行增加删除按钮，批量选择支持勾选多条记录、删除选中和删除全部历史。批量点选、右键整理和删除按钮不触发粘贴。单条收藏或置顶记录删除前确认；批量删除和清空历史默认保留这些记录，可明确勾选同时删除。批量保护在数据库事务内按当前收藏、置顶状态筛选，避免列表状态尚未刷新时误删新受保护记录。

黑色主题的按钮、悬停、选中背景和蓝色文字统一调深。顶部标题与空白区域使用黑色背景，支持拖动并保存位置。
